# Bullet bot status

Last updated: 2026-10-27 23:28 UTC

This file is for the app's coding agent. Questions and decisions stay in [`comments/`](comments/). `BOTS.md` does not name a different status path.

## In progress

Case-capacity estimates for every cartridge that has no published capacity, across `data/cartridges/cartridges.json`, `data/cartridges/bots/bullets.json`, and `data/cartridges/bots/loads.json`. The table is `estimates/case-capacity.json`, regenerated by `scripts/bullets/estimate_case_capacity.py`. Nothing was written into `caseCapacityGrH2O`. The latest run estimated 66 cartridges (geometric median absolute error 1.64 gr, worst 8.7 gr on `.28 Nosler`; parent-case median 1.57 gr, worst 9.82 gr on 6.5 PRC). Sixty cartridges still have no estimate. Details and the storage question are in [`comments/2026-10-27-case-capacity-estimates.md`](comments/2026-10-27-case-capacity-estimates.md).

## Next

1. Hornady's obsolete Dakota drawings print a full labeled dimension set for 7mm, 300, 330, 375, and 416 Dakota. They are not in the library yet. The 404 Dakota and 450 Dakota filenames on that host returned 404.
2. ADG brass pages print brand-specific water volumes and say their brass differs from other makers. Those volumes were not applied.
3. Lesser-known cartridges and wildcats still need a permitted page that prints bullet diameter and case length before a row can go in `data/cartridges/bots/bullets.json`.

## Open questions

[`comments/2026-10-27-case-capacity-estimates.md`](comments/2026-10-27-case-capacity-estimates.md) asks how an estimate should be stored. Until that is answered, estimates stay in `estimates/case-capacity.json` and do not fill `caseCapacityGrH2O`. Hammer's printed case volumes are not on main yet. A published capacity in the owner list, either bot cartridge file, or that Hammer list removes the estimate on the next run.
